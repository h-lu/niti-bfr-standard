# v0.2 下阶段收敛方案

说明:

- 本文记录的是 `wire-like v0.2` 阶段的收敛范围
- 它不是整个项目在所有对象类型上的长期总定义
- 项目的长期方法学边界、A/B/C 保留原则以及 `quicklook` / `formal Af` 的通用关系，以 [AGENTS.md](/Users/wangxq/Documents/niti-bfr-standard-2/AGENTS.md) 为准

## 本阶段唯一目标

把 `formal Af` 的边界与准入条件钉死，停止继续堆算法。

- `quicklook` 只用于快速查看趋势、稳定性和数据可用性，不产出正式结论。
- `formal Af` 只在满足准入条件时给出，且只基于既定正式主量计算。
- `route-level result` 指每条路线自己的量、恢复曲线、Af 估计、QC 与状态；它不等于该路线已经 `formal passed`。
- 对 `wire-like` 而言，`A / B / C` 三条路线都应输出自己的 route-level result，即使当前对象级 formal 只放行 `kappa_fit`。
- 本阶段不讨论“再做一个更强算法”，只讨论“什么情况下可以给正式 Af，什么情况下不可以”。

## In Scope

- 明确区分 `quicklook` 和 `formal Af` 的用途与输出边界。
- 明确区分 `route-level result` 与 `formal passed` 的边界。
- 明确 `formal Af` 的准入条件。
- 钉死正式主量先定为 `kappa_fit`。
- 规定 `x_route_a`、`x_fit`、`kappa_route_c` 等其他量当前不参与对象级正式主量竞争，但仍应输出各自 route-level result。
- 规定不满足准入条件时，只允许给 `quicklook`，不给正式 `Af`。

## Out of Scope

- 新增路线 D、继续细化路线 C、引入新的拟合器或新的时序平滑。
- 重新定义 `Af-95`、`Af-tan` 或改写现有算法口径。
- 把对照量升级为正式主量候选。
- 把“每条路线都有结果”误写成“每条路线都已 formal 放行”。
- 在缺少完整温度同步、缺少高温平台、对象不满足单主弯段前提时强行给正式 `Af`。
- 任何超出“边界与准入条件”之外的功能扩展。

## 实施步骤

1. 在文档层面固定术语:
   `quicklook` = 快速检查与对照输出；`formal Af` = 可进入正式报告的输出；`route-level result` = 每条路线自己的结果与状态。
2. 在文档层面固定正式主量:
   当前正式主量仅为 `kappa_fit`。
3. 在文档层面固定准入条件:
   只有当对象满足单主弯段假设、温度同步可用、恢复过程覆盖到可判定高温端、`kappa_fit(T)` 曲线可稳定提取时，才允许计算正式 `Af`。
4. 在文档层面固定降级规则:
   任一准入条件不满足时，对象级输出自动降级为 `quicklook`，只展示趋势和 route-level result，不给正式 `Af` 数值。
5. 在对外表述上固定口径:
   `x_route_a`、`x_fit`、`kappa_route_c` 等其他量当前仅用于 route-level 输出、交叉检查与 QC，不再进入对象级“正式主量比较”。

## Definition of Done (DoD)

- 文档中已明确写明 `quicklook` 与 `formal Af` 是两类不同输出，不能混用。
- 文档中已明确写明 `route-level result` 与 `formal passed` 不是同一层语义。
- 文档中已明确写明本阶段唯一目标是“formal Af 的边界与准入条件”，不是继续堆算法。
- 文档中已明确写明正式主量固定为 `kappa_fit`，其他量仅作对照。
- 文档中已明确写明 `wire-like` 的 `A / B / C` 三条路线都应有结果输出，但只有 `kappa_fit` 当前可作为对象级正式主量。
- 文档中已明确写明不满足准入条件时，只允许给 `quicklook` 和 route-level result，不给对象级正式 `Af`。
- README 已增加一个最小入口，能把读者直接带到本收敛文档。
